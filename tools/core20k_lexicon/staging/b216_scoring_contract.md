# B216 判分契约：可接受中文等价答案的评分规范（给主开发）

- 适用对象：Batch93 六条（句中释义简答）与 batch79 七条（填空 + 辨识题）的评估实现。
- 参考实现与测试：`b216_scoring_reference.test.mjs`（Node 原生测试，**22/22 PASS**）。契约的数据（每 KU 可接受答案集、辨识题理由关键词集）必须随教学包携带，判分器不得硬编码。
- 本契约不改变任何教学内容；它只规定“学习者答案何时算对”。

## 0. 先说清现状：当前没有中文简答判分器

- 预览页（`batch93-teaching-preview.html`）无答题输入，只有身份核验按钮（下载 Runtime gz、核对 ku_id+词头+类型）。
- 正式学习流（`learning-runtime.js`）是自评式：揭晓后学习者自报 again/good 等（tap flow），不是打字判分。
- 包的 `assessment_type`（句中释义简答）与 `remaining_gate` 中的 `ASSESSMENT_ACCEPTABLE_ALTERNATES` 至今没有运行时实现。
- **结论：当前自评流不需要判分器。** time 的扩写答案（“完成事情所需的时长”）只作为显示的正确答案出现，不参与机器判分，不构成误判风险。**一旦主开发实现打字简答评估，必须按以下契约实现；严格字符串匹配（仅与 `correct_answer` 逐字相等）是被禁止的唯一判分标准。**

## 1. 释义简答（Batch93 型）：可接受答案集 + 归一化

**可接受答案集（每 KU）：** 释义按 `；` 分词 + `correct_answer` + 其按 `；` 分词，全部收录。示例（time）：{时间， 时长， 完成事情所需的时长}。集外答案一律不接受，哪怕“看起来相关”。

**归一化（判分前必做）：** 去首尾空格、压缩内部空白、删除中英标点（；、，,。.!！？?：:；「」『』（）()[]）。归一化后与集合逐项相等才算对；不得用包含关系（“时间”包含于“需要更多时间”不算对）。

**必须接受（测试已覆盖）：** 集合内每一项；标点/空白变体（“时间。”、“ 时长”、“交谈，”）。

**必须拒绝（测试已覆盖）：**
- 句翻译不是词义答案：time 的“需要更多时间”拒绝。
- 错义答案拒绝：time 的“时刻”（ku02 occasion）、here 的“此时”（ku02 discourse）、know 的“认识”（ku02 familiar with）、people 的“民族”（ku02 nation）。
- 片段答案拒绝：time 的“完成事情”（非完整可接受项）。
- 空答案拒绝。
- 两项并列拒绝：“人；个人”作为一次答案拒绝（学习者一次只能答一个义项表述；并列不是答案，是复述释义）。

## 2. 填空（batch79 cloze 型）：大小写容忍，词形严格

- 归一化：trim + 小写。`The`/`the`/`THE` 互通（句首大写不是词形差异）。
- 词形严格：`have` 不接受 `has`（they + have 是规则本身）；`to` 不接受 `for`；`It` 不接受 `they`。
- 空答案拒绝。

## 3. 辨识题（batch79 you/they/it-ku02 型）：verdict + 理由，双条件

- 必须同时满足：(a) verdict 与预期一致（yes/no；中文“是/不”亦可）；(b) 理由包含至少一个可接受理由关键词。
- **理由关键词集必须双语。** batch79 的标准答案本身是英文短语（“No; people in general”），学习者理由可能是中文。参考实现开发中曾因单语关键词集误拒标准答案本身——测试已修正并把该教训记入契约：关键词集 = 英文理由短语 + 中文理由词（如 you：people in general / 一般人 / 泛指；they：unspecified people / 不具体 / 泛指）。
- 裸 verdict 拒绝（只有 “No” 无理由不算对）；verdict 错误拒绝；理由与规则矛盾拒绝（如 “No; the listener”——理由否定了泛指读法）。

## 4. 实现与测试证据

- 参考实现：`b216_scoring_reference.test.mjs`，纯函数（normaliseZh / normaliseWord / scoreMeaning / scoreCloze / scoreIdentification）+ 22 个测试，Node `node --test` 直接运行，**22/22 PASS，0 FAIL**（Batch93 接受/拒绝、Batch79 填空、辨识题三类全覆盖）。
- 主开发实现时：以参考测试的 22 条为验收向量（全部通过方可合入）；可接受答案集与理由关键词集随教学包版本化，包版本变则测试向量同步更新；判分器不得在运行时向学习者透露完整可接受集之外的提示（防刷题面枚举不在本契约内，属防作弊层）。
- 本契约不规定：自评流的 again/good 分级（已有 tap flow 负责）、SRS 间隔算法、发音评分。
